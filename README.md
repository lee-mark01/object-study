## 🔀 Git 및 PR 제출 규칙

### 1. 브랜치 및 PR

**브랜치 형식**

```text
이름/week{번호}
```

예: `seunghee/week01`

**PR 제목 형식**

```text
seunghee - week01
```

**제출 규칙**

1. 최신 `main`에서 주차별 개인 브랜치를 생성합니다.
2. 자신의 폴더에서 학습 내용을 작성합니다.
3. 스터디 시작 전까지 `main`을 대상으로 PR을 생성합니다.
4. PR에 해당 주차의 장별 Markdown 파일을 반드시 포함합니다.
5. 문제가 없는지 확인하고 본인이 바로 Merge합니다.

> `main`에 직접 Push하지 않으며, Merge 후 해당 주차 브랜치는 삭제해도 됩니다.

### 2. 커밋 메시지 (권장)

**형식**

```text
타입: 작업내용
```

**예시**

```text
study: ch01-02 학습 및 실습
docs: ch01 학습 정리
feat: ch01 예제 구현
refactor: ch01 책임 분리
```

| 타입 | 설명 |
|---|---|
| `study` | 학습 내용 전체 또는 복합 작업 |
| `docs` | Markdown 등 문서 작성 |
| `feat` | 예제 코드 구현 |
| `refactor` | 코드 구조 및 설계 개선 |
| `fix` | 오류 수정 |
| `test` | 테스트 작성 및 수정 |
| `build` | 빌드 환경 설정 |

커밋은 의미 있는 작업 단위로 나누는 것을 권장하며, 횟수에는 제한이 없습니다.

### 3. GitHub에서 제출하는 방법

**Markdown만 작성하는 경우**

1. GitHub 웹에서 개인 브랜치를 생성합니다.
2. 자신의 `docs/` 폴더에 Markdown 파일을 작성하거나 수정합니다.
3. 개인 브랜치에 Commit한 뒤 PR을 생성합니다.

별도의 IDE 설치 없이 GitHub 웹에서 진행할 수 있습니다.

<details>
<summary>⌨️ 로컬 Git 명령어 (IDE 사용자)</summary>

아래 예시는 `seunghee`의 1주차 기준입니다.

```bash
# 1. 최신 main 반영
git switch main
git pull origin main

# 2. 주차별 개인 브랜치 생성
git switch -c seunghee/week01

# 3. 학습 및 파일 작성 후 커밋
git add seunghee/
git commit -m "study: ch01-02 학습 및 실습"

# 4. 개인 브랜치 Push
git push -u origin study/seunghee/week01
```

이후 GitHub에서 `main` 대상 PR을 생성합니다.

다음 주에는 최신 `main`에서 `week02` 브랜치를 새로 생성합니다.

</details>
