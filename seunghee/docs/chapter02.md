
# 2장. 객체지향 프로그래밍

## 1. 클래스보다 객체와 협력이 먼저다

객체지향 설계에서는 어떤 클래스를 만들지보다 **어떤 객체들이 어떤 책임을 가지고 협력할지** 먼저 고민해야 한다.

- **객체:** 상태와 행동을 함께 가지며, 자신의 책임을 수행하는 자율적인 존재
- **협력:** 시스템의 기능을 구현하기 위해 객체들이 상호작용하는 것
- **메시지:** 다른 객체에게 행동을 요청하는 수단
- **메서드:** 메시지를 수신한 객체가 요청을 처리하는 구체적인 방법

객체는 메시지를 통해 협력하며, 요청을 어떻게 수행할지는 메시지 수신자가 결정한다.

## 2. 영화 예매 시스템의 협력

영화(`Movie`)와 상영(`Screening`)은 다르다.

- `Movie`: 영화의 제목, 기본 요금 등 영화 자체의 정보
- `Screening`: 특정 날짜와 시간에 실제로 상영되는 사건

영화 예매는 다음과 같은 협력으로 이루어진다.

1. `Screening`이 예매 요청을 받는다.
2. `Movie`에게 예매 요금 계산을 요청한다.
3. `Movie`가 `DiscountPolicy`에게 할인 금액 계산을 요청한다.
4. 계산된 요금으로 `Reservation`을 생성한다.

각 객체는 자신이 맡은 책임을 수행하고, 필요한 작업은 다른 객체에게 요청한다.

## 3. 할인 정책과 할인 조건

| 구분 | 책임 | 종류 |
|---|---|---|
| 할인 조건 | 할인을 적용할 수 있는지 판단 | 순서 조건, 기간 조건 |
| 할인 정책 | 할인 금액을 계산 | 금액 할인, 비율 할인 |

`Movie`는 구체적인 할인 계산 방법을 알지 않고 `DiscountPolicy`에 계산을 위임한다.

- `DiscountPolicy`: 할인 금액 계산의 공통 인터페이스와 흐름
- `AmountDiscountPolicy`: 고정 금액 할인
- `PercentDiscountPolicy`: 비율 할인
- `DiscountCondition`: 할인 적용 여부 판단

## 4. 상속과 다형성

**다형성:** 동일한 메시지를 수신하더라도 실제 객체의 타입에 따라 서로 다른 메서드가 실행될 수 있는 성질

- **컴파일 시점 의존성:** `Movie`는 추상적인 `DiscountPolicy`에 의존
- **실행 시점 의존성:** 실제로는 `AmountDiscountPolicy` 또는 `PercentDiscountPolicy` 객체와 협력
- **동적 바인딩:** 실행 시점에 실제 객체의 메서드가 선택됨

이를 통해 `Movie`를 수정하지 않고도 할인 정책을 교체할 수 있다.

## 5. 추상화와 유연성

추상화는 불필요한 세부사항을 감추고 중요한 개념을 드러낸다.

- 구체적인 할인 방법 대신 `DiscountPolicy`라는 개념에 의존
- 새로운 할인 정책을 추가하더라도 기존 협력 구조를 유지하기 쉬움
- 단, 추상화가 많아질수록 코드의 실제 실행 흐름을 이해하기 어려워질 수 있음

### 상속과 합성

- **상속:** 부모 클래스의 인터페이스와 구현을 물려받음. 부모 구현에 강하게 결합될 위험이 있음
- **합성:** 다른 객체를 포함하고 메시지를 통해 기능을 이용함. 객체를 교체하기 비교적 쉬움

일반적으로 단순한 코드 재사용을 위해서는 상속보다 합성을 선호한다.

### 핵심 정리

> 객체지향 프로그래밍은 객체들이 메시지를 통해 협력하도록 만들고, 추상화와 다형성을 이용해 구체적인 구현이 변경되더라도 협력 구조를 유지하는 것이다.
