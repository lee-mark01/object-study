
# 1장. 객체, 설계

## 1. 기존 설계의 문제점

초기 티켓 판매 프로그램에서는 `Theater`가 `TicketSeller`의 `TicketOffice`와 `Audience`의 `Bag`에 직접 접근해 티켓 판매를 처리한다.

- **이해하기 어려움:** 객체가 자신의 일을 스스로 처리하지 않는 부자연스러운 구조
- **변경에 취약함:** `Bag`이나 `TicketOffice`의 내부 구현이 변경되면 `Theater`도 영향을 받을 수 있음
- **높은 결합도:** `Theater`가 다른 객체의 내부 구조를 지나치게 많이 알고 있음

## 2. 설계 개선: 책임의 이동

핵심은 객체가 자신의 데이터를 직접 관리하도록 책임을 옮기는 것이다.

- **기존:** `Theater`가 티켓 판매 과정의 세부 작업을 직접 수행
- **개선 1:** `TicketSeller`에게 티켓 판매 책임 위임
- **개선 2:** `Audience`에게 티켓 구매와 소지품 관리 책임 위임

결과적으로 `Theater`는 `TicketSeller`에게 입장 처리를 요청하고, 구체적인 처리 방법에는 관여하지 않는다.

## 3. 핵심 개념

| 개념 | 의미 |
|---|---|
| 캡슐화 | 내부 상태와 구현을 감추고 필요한 행동만 외부에 공개 |
| 자율적인 객체 | 자신의 상태를 스스로 관리하고 책임을 수행하는 객체 |
| 결합도 | 객체가 다른 객체의 구현에 얼마나 의존하는가 |
| 응집도 | 객체가 수행하는 책임들이 얼마나 밀접하게 관련되는가 |
| 책임의 이동 | 한곳에 집중된 책임을 적절한 객체로 재분배 |

**좋은 객체지향 설계는 불필요한 의존성을 줄이고, 높은 응집도와 낮은 결합도를 지향한다.**

## 4. 설계와 트레이드오프

- 설계의 목적은 현재 기능을 구현하면서 미래의 변경도 수용하는 것이다.
- 책임을 이동시키면 기존 의존성은 줄어들지만 새로운 의존성이 생길 수 있다.
- 따라서 모든 결합도를 제거하거나 책임을 무조건 분리하는 것이 정답은 아니다.
- 설계는 변경 용이성, 복잡성 등 여러 요소 사이의 트레이드오프다.

### 핵심 정리

> 객체지향 설계의 핵심은 적절한 객체에 적절한 책임을 할당하고, 캡슐화를 통해 변경의 영향을 최소화하는 것이다.
